# TableTalkOnline

協力型カードゲーム「ito」と推理ゲーム「10の扉」をブラウザで遊ぶためのWebアプリ。会話は通話で行い、アプリはカードの配布、例えの記入、並べ替え、公開 (ito) や、質問と解答の記録、回数の管理、答え合わせ (10の扉) を担う。

ロビーでホストがゲームの種類 (ito / 10の扉) を選ぶ。切り替えるとお題 (テーマ) とAIの候補は出し直しになる。

## 遊び方 (ito)

1. ニックネームを入れて「ルームを作る」。作った人がホストになる
2. ヘッダの「招待URLをコピー」で他の参加者を呼ぶ (4文字のルームコードでも入れる)
3. ホストが1人あたりの枚数とお題 (ランダム / 自由入力 / AI生成) を決めて開始する。数字は1〜100から重複なしで配られる
4. 自分の数字は画面上部に常に表示される。自分のカードに例えを書くと全員に見える。例えはめくり始めるまで書き換えられる
5. 自分のカードを列の好きな位置へドラッグして置く (「列の右端に置く」ボタンでも置ける)。列のカードは誰でもドラッグか矢印で動かせる
6. 全員が置き終わると、ホストが「オープン」を押せる。列の小さい側から順にめくれ、各カードにOK/NGが付く。ミスの回数は数えない

## 遊び方 (10の扉)

GM (出題者) がテーマに沿った答えを1つ秘密に決め、ほかの参加者 (回答者) がYes/Noで答えられる質問を重ねて答えを当てる。

1. ホストがロビーで設定を決めて開始する
   - GMの決め方: プレイヤー指名 / ランダム (接続中の人から毎ラウンド抽選。3人以上なら直前のGMは外れる)。指名した人が切断していると開始できない
   - 質問回数: 1〜30回 (既定10回)
   - 嘘の上限: 0〜3回 (既定0回)。回答者の画面に「GMは最大N回嘘をつくことがあります」と出る。残りの回数は出ない
   - 制限時間: なし / 3 / 5 / 10 / 15 / 20 / 30分 (既定なし)。ラウンド全体の持ち時間で、1問ごとの制限は無い
   - テーマ: ランダム (内蔵リスト) / 自由入力 / AI生成 (候補は全員に見え、ホストが選ぶ)
2. 開始するとGMが決まり、テーマが全員に公開される。GMが答えを入力して確定すると質問が始まる
3. 回答者は「質問」か「解答」を選んで提案する。提案者以外の回答者全員が「OK」を押すとGMへ届く。承認が必要な人 (接続中・GM以外・提案者以外) がいないときは自動で届く。承認が必要な人が切断・退室して、残りが全員OK済みになった場合も届く
   - 承認待ちと未回答の提案は、回答者の誰でも取り消せる。取り消しと却下は回数を減らさない
   - 1人が同時に出せる承認待ちは2件まで。承認待ちと未回答の合計は残り回数まで
   - 質問で答えそのものを聞いても質問として答えられる。当てるときは「解答」で出す
4. GMは質問にYes / どちらかといえばYes / 分からない / どちらかといえばNo / No、解答に正解 / おしい / 不正解で答える (却下もできる)。嘘の残りがあれば質問の回答に嘘印を付けられる。回答された質問と解答は回数を1つずつ減らす。解答が「正解」なら回答者の勝ち
   - 人のGMは、回答済みの判定をログの「訂正」で直せる (ラウンド中だけ。回数は変わらず、全員のログに「訂正: No → Yes」と出て、GM以外に通知が出る)。解答の「正解」と最終解答への判定は、押す前に確認が出る
5. 回数を使い切ると最終解答を1回だけ出せる (GMが却下したら権利は残る)。「正解」なら勝ち、それ以外は負け
6. ホストかGMは、質問中と最終解答中に「延長 +1 / -1」で回数を変えられる (合計99回まで、使用済みと処理中の数より減らせない)。最終解答中に+1すると質問に戻る。回答者は「延長をお願い」でホストとGMに知らせられる
7. 制限時間があるときは、答えが決まった時点から残り時間が全員に出る (残り1分で色が変わり、残り10秒で脈打つ)。時間が切れると承認待ちの提案は取り消され、新しい提案は出せなくなる。GMへ届いている提案に答え終わると最終解答の段階へ進む。時間切れだけでは負けにならない
   - 最終解答の段階には制限時間が無い
   - ホストかGMは「時間 +1分」で締切を延ばせる。時間切れのあとに押すと、回数が残っていれば質問に戻る。時間切れの間に「延長 +1」で回数だけ足しても質問には戻らない
8. 結果画面で答え、勝敗、嘘印を含む全ログが全員に公開される。「ログをコピー」でテキストにできる。ホストがロビーへ戻すと、設定はそのまま引き継がれる

途中で終わる場合:

- ホストは確認の後にラウンドを中止できる。答えとログを公開してから、結果画面経由でロビーへ戻る
- GMが30秒以上切断すると、ラウンドは中止になる (答えを知らない人へGMを移せないため)
- 回答者が全員退室すると、ラウンドは中止になる
- 途中から入った人は回答者に加わる

### AIがGMを務める

GMの決め方で「AI」を選ぶと、AIがテーマから答えを1つ決め、参加者全員が回答者になる。1人でも遊べる。ASK APIの設定 (下の「デプロイ」) が無いサーバでは選べない。

- 開始するとAIが答えを決める。決められなかったらロビーへ戻る。同じルームで前に使った答えは避ける
- 提案と承認の流れは同じ (回答者が1人なら承認は自動で通る)。承認された提案は古い順に1件ずつAIが答える。AIが答えている提案は取り消せない
- 質問には5段階、解答には正解 / おしい / 不正解で答える。表記ゆれ・同義語は正解、上位・下位の分類や関連の深いものは「おしい」。最終解答では「おしい」も負け
- 嘘の上限が1以上なら、サーバが上限の範囲でAIの回答を反転させる (分からないは反転しない)。どれが嘘かは結果画面で公開する
- 解答の判定理由は結果画面でだけ出る
- AIの応答に失敗したら (30秒のタイムアウトを含む)、回数は減らず、ホストが「再試行」できる
- 延長の+1 / -1はホストが押す

リロードしても同じ席に戻る。サーバを再起動すると全ルームが消える。

## 開発

```sh
npm install
npm run build && npm start   # http://localhost:47213
# または npm run dev:server と npm run dev:client を別々に起動 (http://localhost:5173)
```

## デプロイ

```sh
docker compose up -d --build
```

AIお題 (10の扉ではテーマ) と10の扉のAI GMは、社内のASK API (NoteDockと同じ窓口) を使う。使うなら`compose.yaml`と同じ場所の`.env`に次を書く。`ASK_API_KEY`か`ASK_PROJECT_ID`が無ければ、AI生成は内蔵リストのお題に切り替わり、10の扉のAI GMは選べなくなる。

```sh
ASK_API_KEY=<APIキー>
ASK_PROJECT_ID=<プロジェクトID>
# 省略時の値
# ASK_API_URL=https://langchaindemo.heroz.jp
# ASK_MODEL=claude-55-sonnet-thinking
# 10の扉のAI GMの既定のモデル (gpt-6-luna-thinking か gpt-6-luna。ロビーでホストが選び直せる)
# DOORS_MODEL=gpt-6-luna-thinking
```

10の扉のAI GMの既定は`gpt-6-luna-thinking`。実機のASK APIで確かめた結果は次のとおり。`gpt-6.1-luna`・`gpt-61-luna` (各`-thinking`付きも) は400、`gpt-6-luna`と`gpt-6-luna-thinking`は200で答えが返った。ロビーでホストが選べるのはこの200が返った2つだけで、`DOORS_MODEL`も2つのどちらかでなければ無視して既定に戻る。

`claude-home` volumeは不要になった。旧構成から移すときは`docker volume rm`で消してよい。
